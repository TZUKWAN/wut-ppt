# wut-ppt 设计系统（为什么这样设计）

> 本文档记录从"V15 太丑"到"V17 达标"的完整分析，是技能的质量基线。
> 改任何一条之前，先想清楚当初为什么定这条。

## 一、失败教训（V15 丑的根因）

1. **直接画大色块基础形状**：椭圆、菱形、大箭头纯平涂 → 2003 年 SmartArt 既视感。
2. **关键词漂浮**：每页只有几个词，4000 字源文档的信息全丢 → 又丑又空。
3. **文字塞进窄形状**：菱形里硬塞文字 → 断词（"缺乏有效抓 手"）。
4. **无网格无对齐**：形状位置随意、间距不一。
5. **占位符残留**：章节页占位文字没替换，出现坏页。

结论：**程序画形状不等于丑，丑的是"大色块 + 无层级 + 无密度"。**
正确路线是"设计系统"：固定色板、固定字号阶梯、固定版式目录、内容先行。

## 二、五条硬规则（用户验收标准，不可违反）

| # | 规则 | 实现 |
|---|---|---|
| 1 | 全文最小字号 ≥ **12pt** | build_deck 所有正文 12pt 起；check_deck 强制检查 |
| 2 | 每个要点必须**独立形状包裹** | cards/timeline/badge_grid 均"一点一卡 + 序号圆徽" |
| 3 | 必须有**视觉逻辑引导** | flow_chain 箭头链、shape_row 连接线、timeline 时间轴、compare_rows 箭头 |
| 4 | **高信息密度** | 要点 = 引导语 + 完整解释句；每页 300–600 字 |
| 5 | **不允许大片空白** | 垂直流引擎自动把剩余空间分给可伸展 zone，填满整页 |

## 三、颜色纪律（三件套 + 中性色）

- 主蓝 `#00469A`（校徽蓝）：标题条、列头、形状主色
- 金黄 `#FBC540`：小面积点缀（金条、箭头、徽章、节点）——不大面积铺
- 强调红 `#C00000`：仅结论、关键数字、链条末节、页标题（模板自带）
- 中性色：正文 `#262626`、辅助灰 `#595959`、卡片底 `#F4F7FB`、标签底 `#EAF1F9`、细线 `#D9D9D9`
- 派生蓝：深蓝 `#003371`（引导语/表头文字）、连接蓝 `#3D6FB0`
- **禁止**引入以上之外的颜色；时间轴节点允许蓝/金/红三色（三件套内）

## 四、字号阶梯

| 用途 | 字号 | 用途 | 字号 |
|---|---|---|---|
| 页标题（模板自带） | ~28pt | 列头/卡片标题 | 12.5–13pt |
| 横幅主行 | 14pt | 要点正文/表格正文 | **12pt（下限）** |
| 导语段 | 13pt | 结论条 | 12.5pt |

字体：全文微软雅黑（latin + ea + cs 均设置），禁用默认 Calibri。

## 五、版式机制（垂直流引擎）

```
正文区 y ∈ [1.02, 6.95]，x ∈ [0.45, 12.88]（英寸）
页面 = zones 列表，垂直堆叠，区间距 0.14
引擎两遍布局：
  ① 按内容估算每个 zone 高度（CJK 按 1em/字、西文 0.55 折算行数）
  ② 剩余空间按比例分给可伸展 zone（cards/timeline/badge_grid/compare_rows/kv_rows/table）
     超出则整体压缩 → 任何内容量都刚好填满，零大片空白
```

卡片内部：要点卡均分列高，文字垂直居中。

## 六、形状库（禁止纯大色块）

| 形状 | 用途 |
|---|---|
| 圆角矩形（小圆角 0.055） | 要点卡、列头 |
| 圆形 OVAL | 序号徽章、时间轴节点 |
| CHEVRON 箭头 | 递进链（咬合格式） |
| RIGHT_ARROW | 映射关系箭头（金色） |
| 六边形 HEXAGON | 工作组、制度小签 |
| 平行四边形 PARALLELOGRAM | 对象标签、横幅装饰 |
| 三角形 | 结论条引导符（红色） |

规则：形状只做"容器"和"引导"，**文字永不塞进装不下的形状**（徽章只放数字，菱形禁用）。

## 七、模板结构（assets/template.pptx）

- 5 张样板页：`0=封面` `1=目录` `2=章节页` `3=正文页(红标题)` `4=表格样例`
- 母版自带：底部蓝条 + 金色校徽条（所有页自动继承）
- 生成器克隆样板页后**文字替换**（"此处输入一级标题"等占位语），正文页在标题下方画 zones；最后删除 5 张样板页
- 占位符清单见 `scripts/check_deck.py` 的 DIRTY_MARKERS

## 八、工作流（内容先行，视觉自检闭环）

```
① 拆源文档：每段原文 → 落到哪一页（覆盖率 ≥90%，可用表格核对）
② 选配方写大纲 JSON（references/outline_contract.md 的页面配方）
③ 生成：python scripts/build_deck.py 大纲.json 输出.pptx
④ 自检：python scripts/check_deck.py 输出.pptx
⑤ 视觉自检：python scripts/export_preview.py 输出.pptx → 逐页看 PNG
   （机器检查替代不了人眼：断词、拥挤、空白、引导缺失只能看出来）
⑥ 不满意 → 改 JSON 回到 ③；改样式 → 改 build_deck.py 后回到 ③
```

**第 ⑤ 步不可省。** V15→V17 的每一版进步都来自导出 PNG 逐页看图。
